# Full electrical verification and optional quick structural checks

GUI GO defaults to full electrical verification. Turn off **Full simulation verification** in SETUP to use quick mode. Quick mode reads the selected datasheet, extracts and validates its records and physical pin map, then asks the selected provider for a self-contained model. It skips AI test fixtures, supplemental web search and the full electrical simulation suite. Each candidate receives structural checks and, when LTspice is configured, an unpowered operating-point load capped at five seconds. All extracted requirements are retained, including conditions, relative limits and citation warnings. The authoring prompt excludes simulation recipes and repeated excerpts.

Local checks screen subcircuit boundaries, duplicate component names, physical pin mapping, expression braces and unresolved subcircuit references. The app generates the standard symbol from the model's declared terminal order. It allows one draft plus at most one structural repair, and reuses a model only when its specification and structural-check receipt match its current hash. API duration still depends on the selected provider/model/reasoning setting; this is not a fixed-time generation guarantee.

The result is labelled **Sanity checked; electrical accuracy unverified**. Its machine status and all electrical rows remain UNKNOWN, never simulated PASS. The model card and sanity-report.json record the local checks and one bounded LTspice load check: LTspice must parse the library and solve a generic unpowered operating point inside a five-second limit. That load check measures no datasheet behaviour, and it is reported honestly as `loaded`, `inconclusive`, `unavailable` or `cancelled`; a model the simulator rejects outright is never published. These checks are not a complete LTspice parser and do not establish convergence, electrical accuracy, timing, stability or temperature performance. The example is a connection template that needs appropriate supplies, inputs, loads and an analysis.

SETUP has **Full simulation verification (slower)**, on by default and saved in this extracted folder's config. **Run full verification** starts the same full workflow after a quick result. It reuses extraction caches, plans independent measurement circuits, runs real LTspice and may repair a model against the frozen requirements. Only observed simulator measurements can produce PASS. This workflow can take substantial time.

CLI: `boardmodeler model build --part PART --datasheet file.pdf --out folder --sanity --allow-remote`. The existing CLI without --sanity and the low-level MakeModelRequest API retain full verification for backward compatibility. The running old executable does not change when a new version is downloaded.

Quick-mode tests use explicitly synthetic circuits to verify control flow, structural failures, cache invalidation, bounded repair, tamper detection, stale-candidate rejection and honest export. They do not certify the accuracy of generated hardware models.
