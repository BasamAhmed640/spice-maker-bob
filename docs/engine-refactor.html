# Spice Maker: core-engine refactor brief

Repository: https://github.com/BasamAhmed640/spice-maker

Reviewed baseline: `b1ced1cb238a046ee322a89db368bab946bcdf34` (2026-09-28). This is a source and committed-evidence review; no simulator benchmarks were rerun and no repository code was changed. Recheck HEAD and local instructions before implementation.

## Recommendation

Make the engine an **evidence-to-model compiler**: verified datasheet evidence becomes a typed, family-specific model design; reviewed code generates the SPICE library; independently frozen, code-built benches qualify the actual output in LTspice.

AI extracts evidence in the default path. It does not invent tests, emit SPICE, alter limits, or repair the model at runtime. Keep the existing AI-authoring workflow as an explicitly selected legacy mode. This implements the model-generation direction already recorded in D-048, with the model-only product scope of D-052.

The practical benefit is reproducibility and traceability: the published library, its final parameters, its pinout and its measured claims all refer to the same candidate. This should reduce avoidable authoring work for supported families; accuracy and speed still require measurement. A deterministic model can consistently be wrong.

## Why this is the right refactor here

1. `models/buck_switching.py` already has `ParameterOrigin`, `BuckSeed`, contract-driven parameter mapping, physical pins, and SW/AVG rendering. Generalize this working slice instead of starting a new generic synthesis framework.
2. `pipeline/make_model.py::_seed_buck_template` treats it as a seed before AI repair. Publication explicitly warns that, after repair, parameter origins describe only the starting seed. Preserve structured design as the source of the final library to close this gap.
3. `models/templates.py` already contains `FamilyTemplate` and `TemplateContract`. Assess reusable validation and renderer ideas, but do not create a third competing template system. Its fixed logical ports and embedded application deck are not a ready replacement for the current physical-package model path.
4. Production binding can call `test_planner.plan_bindings`. Meanwhile reviewed deterministic buck benches and waveform evaluators already exist in `authoring/buck_system_fixtures.py` and the M4b1 experiment. Bring those capabilities into production with independent qualification contracts.
5. Preserve the frozen spec, citation checks, truthful UNKNOWN results, simulator evidence and cache protections. Those are assets, not architecture to discard.

## Target architecture

Verified evidence branches into two independent products:

- **Model branch:** evidence -> family match -> `ModelDesign` -> deterministic renderer -> candidate `.lib` and `.asy`.
- **Qualification branch:** evidence + reviewed bench definition -> frozen `QualificationPlan` -> LTspice measurements -> per-check verdicts.

The qualification runner consumes the candidate, but it must never derive acceptance limits from the candidate's parameter values. Publication combines final design provenance with measured results and explicit gaps.

Suggested boundaries; names are proposals, not a demand for a new framework:

| Boundary | Owns | Does not own |
|---|---|---|
| Evidence adapter | Existing `Requirement`, `PinDefinition`, citation status, source document hashes, normalized units | Invented values, simulator verdicts |
| Family definition | Matching rules, supported topology/modes, parameter schema, renderer version, declared capability limits | Device-specific proof of accuracy |
| Model design | Part/package, exact physical pins and aliases, family/version, SW/AVG mode, parameter values and origins, required external connections | Bench limits or PASS declarations |
| Qualification plan | Source requirement IDs, independently sourced bounds, conditions, external bench parts, stimuli, state guards, measurement windows, applicability | Repairable model settings |
| Candidate record | Design digest, rendered library/symbol hashes, family/renderer versions, parent or baseline identity when relevant | Reusable proof without validation |
| Qualification result | Actual measurements, per-row verdict/reason, tested domain, deck/log/raw hashes, candidate identity | Claims about unmeasured temperature, process, protocol or behavior |

Use strict versioned records and deterministic serialization. Start with a typed buck design, then extract common interfaces only where a second family needs them. Adapt existing records instead of duplicating the whole extraction schema. Separate IC parameters from fixture/instance parameters; AVG's external inductor is not an IC datasheet property.

Parameter provenance should distinguish cited, derived from cited data, and explicit template assumption/default. A value with missing or contradictory evidence cannot silently become cited. A required unsupported value stops that family path with a reason; permitted approximations remain visible and restrict claims.

## Concrete example

For the cited TPS54332 VREF row, the model can render a nominal `VREF=0.8 V`. Independently, the qualification plan retains the cited `0.772–0.828 V` bounds and its recorded circuit conditions. A deliberately wrong `VREF=0.72 V` candidate must fail that unchanged test. Moving the model value must never move the judge's bounds.

The committed M4b1 report already demonstrates this kind of clean/wrong-value control for four rows in SW and AVG. Reuse the method and measured fixtures; do not describe those four rows as whole-model qualification.

## Implementation sequence

### PR 1: preserve a typed buck design through rendering

- Read `AGENTS.md`, D-041, D-047 through D-052, the template catalog, and the current milestone plan. Confirm current behavior and entry points from code; old documentation is not uniformly current.
- Separate the design values/pins/provenance from `BuckSeed.library_text`, using a strict `BuckDesign` or equivalent record. Keep `seed_from_spec` as a compatibility adapter.
- Make rendering a pure function of the validated design and renderer version. Maintain existing SW bytes, physical pin order, aliases, separate PowerPAD behavior, AVG semantics and parameter provenance.
- Save a versioned design record beside candidate metadata and bind it to the exact library hash. Preserve existing public artifacts and old-directory reopening. Existing free-form libraries remain reopenable without fabricated structured provenance.
- If legacy AI repair changes the rendered bytes, keep the design as seed provenance and mark its final-artifact association invalid. PR 1 must not claim to reconstruct final parameters from arbitrary SPICE text.
- Prove deterministic serialization/rendering, rejected invalid inputs, correct cited/default distinctions, and SW/AVG pin/parameter parity. Test the matching logic's rejection of a different topology.
- Do not change default routing, equations, scoring, status names, provider transport, or the UI in this behavior-preserving PR. Report actual checks and limitations.

### PR 2: make independent family qualification reusable

- Adapt the reviewed M2 bench builders and M4b1 waveform/state evaluators into production modules. Keep command-line experiment scripts as thin callers. Do not import tool scripts into the product.
- Introduce a frozen qualification plan backed by raw verified requirements and reviewed conditions. Preserve the original spec digest and row coverage; add supplemental qualification without dropping legacy rows or relabeling missing measurements.
- Require observable correct operating state before comparing numbers. Keep each operating point explicit. Include clean/fault controls for every newly generalized evaluator and a second compatible buck part where evidence exists.
- Distinguish all executed checks passing from family qualification. Qualification needs a declared mandatory checklist and operating domain; missing mandatory checks cannot disappear from its denominator.
- Reuse LTspice execution, artifact handling and existing evidence/cache protections. Hash model, design, spec, bench definitions, evaluators, renderer and simulator inputs relevant to reuse. A neighboring checksum file alone does not make a cache trusted; fresh-process validation rules remain.
- Inject a judge/report callback into the author loop instead of monkey-patching `loop.run_harness` through `_observe_reports`. Preserve build exclusion until other shared state is demonstrably isolated; removing one global wrapper does not establish concurrency safety.

Two measurement-consistency issues deserve separate, evidenced changes during this phase, not silent changes in PR 1. Generic mean/RMS calculations in `circuit_probe.py` use sample averages, while M4b1 uses time integration; choose and test time-weighted physical metrics for nonuniform samples. Also, `harness._judge` normalizes unsigned current magnitude while `validation_cache.progress_score` ranks signed raw values; share per-row normalization/comparison so legacy repair ranking agrees with verdicts. These are source-audit findings, not newly reproduced simulator failures.

### PR 3: introduce the code-built route, then promote it

- Add explicit engine selection, for example `template` and `legacy-ai`. Keep generation engine selection separate from `sanity` versus full verification.
- With already verified local inputs and an implemented family, the code-built route must not construct or check an author backend, call the AI test planner, generate SPICE remotely, or repair candidates with AI. Extraction may still require the selected provider when verified inputs are absent.
- Move provider/network checks to the stages that actually require them. Prove the local compile/qualify route with a socket tripwire and a backend stub that fails if called. Preserve the existing internet-access policy for remote extraction and legacy authoring.
- Never silently switch a failed family route to AI authoring. Return the precise unsupported/missing-evidence reason. A generic pin-only output is allowed only when that separate implementation and its evidence exist; do not label it functionally equivalent.
- Promote each supported family deliberately after compatibility and qualification checks. Preserve legacy CLI/API/result behavior through adapters, and keep old saved outputs usable. Do not switch all devices to the buck path.
- Keep M4b2/M4b3 and the package-pinout gate tracked as unfinished until their evidence exists. Refactoring does not complete those physics/qualification milestones.

### Later work

Complete the buck qualification gaps, then add one genuinely different family to validate the interface. Extend incrementally toward the catalog. Do not implement all 22 families, a universal circuit graph, a new optimizer, distributed agents, or a new simulator abstraction in this refactor.

If a valid fixture exposes missing physics, change the reviewed family renderer in a separately tested code change. Runtime parameter tuning or structured AI patches would be a separate design decision; they are not part of the D-048 default.

## Acceptance criteria

1. Same verified input, design and renderer version produce identical canonical design and library bytes. Published provenance refers to the delivered bytes.
2. Physical package pin order, subcircuit ports and symbol `SpiceOrder` agree; required external ties stay external. Preserve existing checks and explicitly report the still-open M6 publication gate.
3. Limits, citations, conditions, coverage and frozen bench definitions cannot be mutated by candidate generation. A wrong model value fails an unchanged criterion.
4. The implemented local family route makes zero planner/author/repair API calls and no unnecessary provider-availability checks. Unsupported cases are explicit, with no hidden fallback.
5. Preserve all existing PASS/FAIL/UNKNOWN evidence. Missing simulator is BLOCKED when simulation is required; quick checks do not claim electrical accuracy. AVG ripple/edge checks remain UNKNOWN. A template default or a simulator exit code is not electrical proof.
6. Any new claimed electrical PASS has actual LTspice measurements bound to the exact candidate, test conditions, and artifact hashes. Synthetic control data is labeled synthetic.
7. Reproduce frozen TPS54332 and LM358 controls when changes affect model/harness behavior, explaining every changed verdict. The historical TPS baseline includes failures and unknowns; green software tests must not erase them.
8. Measure extraction, compile, simulation and total time separately, alongside provider calls, coverage and verdict changes. Treat the documented 5–10 minute goal as a benchmark target, not a promised speedup.
9. Run focused affected suites, required lint/format checks, shared-core manifest checks, and `git diff --check`. Update `docs/STATUS.md` with commands actually run and `docs/DECISIONS.md` with new architectural decisions. Do not claim an unavailable simulator run succeeded.

When relocating code, explicitly update fingerprint/manifest traversal: current validation-cache engine hashing scans flat Python files in `authoring`, `simulation` and `domain`; the shared-core tooling also has an explicit scope. A new package or JSON renderer contract must not disappear from invalidation or parity checks.

The other edition is outside this repository unless available and explicitly included in the implementation task. Maintain the shared-core contract here and report unavailable cross-edition validation without claiming it.

## Non-goals

No board checker, board reports, CAD/netlist import, UI redesign, provider rewrite, installer/release work, broad family expansion, or new electrical-accuracy claims merely from reorganizing code. Preserve documented transport, secret handling and execution restrictions.
